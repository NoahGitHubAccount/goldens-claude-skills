# 格式規範與黃金範例

本檔提供完整的欄位定義、三段式步驟細節，以及一組以「訂單出貨管理系統」為例的黃金範例（通用化示意，非任何特定產品），供生成時對照。

## 欄位定義

| 欄位 | 必填 | 內容規則 |
|---|---|---|
| 情境名稱 | 是 | 業務語言。樣式：「如何<動作>」或「<業務>作業/流程/說明」。一句話，不含技術型別。 |
| 使用角色 | 是 | 該情境涉及的所有角色。跨角色協作時全部列出（可換行）。 |
| 步驟 | 是 | 三段式：前置準備 / 驗測情境步驟 / 結果檢視。 |
| 進度 | 是 | `已完成` / `製作中` / `待撰寫`。標撰寫狀態，非執行結果。 |
| 對應需求編號 | 是 | 如 `REQ-01-01`；無來源標 `（待補）`，不留空。 |

## 三段式步驟——標準寫法

```
前置準備：
  以具<角色/權限>的帳號登入系統。<其他資料前提，如「人事介接已同步該人員」>

驗測情境步驟：
  1. 由左方功能選單依序點選「<選單>」→「<子選單>」。
  2. 點選頁籤「<頁籤>」，點擊「<按鈕>」按鈕開啟「<視窗>」。
  3. 於畫面中輸入以下欄位資料：
     3.1 <欄位A>
     3.2 <欄位B>（可維持預設 <值>）
  4. 點選[<送出動作>]，<可觀察結果，如「系統顯示新增成功」/「資料狀態變為待揀貨」>。
  5.（換 <B 角色> 登入）<B 角色> 於【<畫面>】看到此筆資料，狀態為「<狀態>」。

結果檢視：
  返回「<列表>」，確認 <可驗證的最終狀態>。
```

## 撰寫技巧速記

- **麵包屑導航**：`【一級】>【二級】>【三級】`，寫死功能入口路徑。
- **動作—結果配對**：每個操作動詞後緊接一個可觀察結果（狀態詞 / 列表出現 / 提示訊息 / 欄位更新）。
- **狀態詞引號標示**：用「」框住狀態名，方便人眼掃描狀態流轉鏈。
- **子編號表分支**：5.1 / 5.2 / 6.1 / 6.2 表示同一步的多條路徑。
- **換手明寫**：跨角色處註明「（換 X 角色登入）」，這是整合測試最容易漏的地方。
- **欄位驗證清單化**：要檢視的表格欄位逐一列出（序號、帳號、姓名、操作時間…）。

## 黃金範例

### 範例 A — 三段式最完整（如何新增商品分類）

| 欄位 | 內容 |
|---|---|
| 情境名稱 | 如何新增商品分類 |
| 使用角色 | 系統管理員 |
| 步驟 | **前置準備**：以具系統管理權限的帳號進入系統。<br>**驗測情境步驟**：<br>1. 由左方功能選單依序點選「系統管理」→「基礎資料維護」。<br>2. 點選頁籤「商品分類」，點擊「新增」按鈕開啟「新增分類」視窗。<br>3. 於畫面中輸入以下欄位資料：<br>　3.1 所屬上層（可選擇或點「+」新增上層分類）<br>　3.2 分類名稱<br>　3.3 分類代碼<br>　3.4 排序（可維持預設 0）<br>**結果檢視**：返回「商品分類」列表，確認新建分類顯示於列表中。 |
| 進度 | 已完成 |
| 對應需求編號 | （待補） |

> 重點：開頭前置、欄位用子編號逐項列、結尾有明確列表斷言。

### 範例 B — 狀態流轉 + 跨角色交接（訂單揀貨出貨流程）

| 欄位 | 內容 |
|---|---|
| 情境名稱 | 訂單揀貨出貨流程 |
| 使用角色 | 倉管人員 |
| 步驟 | 1. 倉管人員進入【訂單管理】>【出貨作業】>【揀貨單】建立揀貨資料<br>2. 輸入資料後點選[新增]，系統顯示新增成功<br>3. 新增完畢，剛登記的資料出現在列表中，且狀態為「待揀貨」<br>4. 勾選項目<br>5. 倉管人員印出【揀貨清單】<br>6. 倉管人員點選[送出]交付物流人員 |
| 進度 | 已完成 |
| 對應需求編號 | REQ-01-01 |

> 重點：狀態鏈（新增→「待揀貨」→送出）、動作—結果配對、結尾交棒給下一角色。

### 範例 C — 多角色協作 + 多分支（訂單出貨派送作業）

| 欄位 | 內容 |
|---|---|
| 情境名稱 | 訂單出貨派送作業 |
| 使用角色 | 倉管人員 → 出貨主管 / 物流人員 |
| 步驟 | 1. 倉管人員進入【訂單管理】>【出貨作業】>【出貨單登錄】<br>2. 輸入資料，點擊新增<br>3. 勾選項次<br>4. 依出貨類型點選[送主管覆核]或[送物流]<br>5.1 點選[送主管覆核] → 資料狀態變為「待覆核」<br>5.2（換出貨主管登入）於【出貨覆核清單】看到此筆，可續核准送物流或退回<br>6.1 點選[送物流] → 資料狀態變為「待出貨」<br>6.2（換物流人員登入）於【物流出貨清單】看到此筆，可續出貨或退件 |
| 進度 | 已完成 |
| 對應需求編號 | REQ-02-01 |

> 重點：分支子編號、每分支都標狀態與換手對象，整合測試的「跨角色資料流動」在此最清楚。

### 狀態機參考（範例系統）

`待揀貨 → 已揀貨 →（覆核）→ 待出貨 →（出貨）→ 已出貨 →（簽收）→ 已簽收 →（手動封存）→ 已封存`

封存後不可修改/刪除——這類「終態約束」是很好的結果檢視斷言來源。
