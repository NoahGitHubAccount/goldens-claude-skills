# 01 - Context Map：CLAUDE.md 地圖設計原則

## 核心理念

不要把所有專案規則、架構決策、歷史記錄塞進單一 `CLAUDE.md`。**過載的上下文視窗會讓 Agent 失去焦點並產生「上下文焦慮」**。

`CLAUDE.md` 應該是**地圖**，不是百科全書。它的工作是「告訴 Agent 該去哪裡找答案」，而非「把所有答案攤平給 Agent」。

## CLAUDE.md 應該包含

1. **專案一句話定位**（不超過兩行）
2. **核心技術棧**（語言 / 主要框架，三行內）
3. **絕對禁止事項**（最多 5 條，每條一行）
4. **語言 / 風格規則**（如「所有回應使用繁體中文」）
5. **指引到子文件的連結地圖**：
   - 詳細架構 → `docs/architecture.md`
   - 過去錯誤 → `learnings.md`
   - 當前進度 → `status.md`
   - 任務計畫 → `plan.md`
   - 設計決策 → `docs/adr/`

## CLAUDE.md 不應包含

- 完整 API 文件（放 `docs/api.md`）
- 詳細部署步驟（放 `docs/deployment.md`）
- 變更日誌（放 `CHANGELOG.md` 或 git log）
- 大段 prompt 範本（封裝為 skill）
- 超過 100 行的內容 — 超過就拆分

## 寫法檢核

- [ ] CLAUDE.md 全文 ≤ 100 行
- [ ] 至少 3 個指向子文件的相對路徑連結
- [ ] 沒有重複 README.md 已寫過的內容（README 給人類，CLAUDE.md 給 Agent）
- [ ] 含明確「不要做 X」清單，而非僅「應該做 Y」
- [ ] 子文件實際存在（連結不死）

## 與 README.md 的分工

| 面向 | CLAUDE.md | README.md |
|---|---|---|
| 目標讀者 | Agent | 人類 |
| 重點 | 行為約束、地圖 | 安裝、啟動、使用 |
| 風格 | 條列、簡短 | 敘事、含截圖 |
| 內容 | 禁止事項、決策慣例 | 功能介紹、貢獻指南 |

兩者可以互相連結，但**內容不重複**。
